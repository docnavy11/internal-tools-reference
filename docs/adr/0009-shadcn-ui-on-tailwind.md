# 0009 shadcn/ui components on Tailwind CSS 4

Accepted, 2026-09-04

## Context

Internal tools are tables, forms and dialogs. A full component library such as
Ant Design or Mantine gives those out of the box but imposes its look and its
upgrade cadence. shadcn/ui copies component source into the repo, styled with
Tailwind, and is what most startup front-end developers now expect. Tailwind 4
moved configuration from `tailwind.config.js` into CSS. Class names are unchanged.
The configuration move is the one part of this stack where the builder's depth is
less than ideal.

## Decision

shadcn/ui on Tailwind 4, initialised with the shadcn CLI rather than hand-written
configuration, then committed. TanStack Table renders through the shadcn table
primitives; the `DataTable` and form field components in `client/platform/` are
ours and are the real reusable surface.

## Consequences

- No UI dependency to upgrade; the components are source in the repo.
- The template must ship the higher-level components (`DataTable`, filter bar,
  `FormField` wrappers, `ConfirmDialog`, `EmptyState`, `PageHeader`) because
  shadcn only provides primitives.
- Tailwind and shadcn setup is generated by their CLI at phase 1 and verified by
  building, not written from memory.
